# 安全设计

## 1. 威胁模型与核心保证

主要威胁包括恶意客户端伪造动作/版本/身份、窃取会话、枚举账号、WS 重放、管理员越权、私牌通过投影/日志/历史泄露、机器人作弊、SQLite 并发造成重复资金操作、崩溃窗口重复结算，以及公开仓库泄密。

核心保证：客户端永不权威；管理员不能作弊；未公开信息只进入最小必要进程/投影；正式筹码变更原子、幂等、可审计；安全失败默认拒绝且不自动增发筹码。

## 2. 认证与密码

- 使用 PHP `password_hash`（部署时优先 Argon2id，可用性不足时 PASSWORD_DEFAULT）和 `password_verify`；登录成功按 `password_needs_rehash` 升级。
- 设置合理最小长度，允许密码管理器长密码；不做泄露用户名的差异错误。登录、重置、邀请码和 CLI 恢复限速/延迟并审计。
- Session ID 使用安全随机，数据库只存令牌哈希；Cookie 为 Secure、HttpOnly、SameSite=Lax，登录/提权/改密后轮换。
- 管理员重置密码会撤销目标全部会话/WS ticket，设置强制改密；响应不记录/返回固定管理员密码。
- CLI 首管理员创建/恢复只能在服务器终端运行，交互读取或安全输入临时秘密，写审计；禁止万能密码、隐藏路由和硬编码凭证。

## 3. 授权

后端每个用例同时检查角色、资源关系和领域状态：管理员接口需要 A；房主管理需要 owner；个人资料/历史需要 Self/参与关系；普通房禁止游客。Vue 路由守卫仅改善体验，不是安全边界。

管理员进入牌桌时以普通 Human Player 身份；旁观时与普通旁观者同投影。后台无接口读取牌堆/未公开牌、设置发牌、修改底池/escrow 或即时控制机器人。异常关闭只能触发受审计恢复流程。

## 4. Web 与 WebSocket 防护

- 全站 HTTPS/WSS、HSTS、明确 Origin allowlist、安全 Cookie、CSRF token、CSP、`frame-ancestors 'none'`、`nosniff` 和严格 Referrer-Policy。
- 输出按上下文编码；展示名等用户内容按纯文本处理；API JSON schema 白名单和大小/深度限制。
- WS 一次性短票据绑定主体/房间/期限，握手校验 Origin；命令校验 request_id、hand_id、version、当前行动者和合法范围。
- 按 IP、账号、连接、房间分别限速；异常重放/枚举触发审计和临时抑制，不把 IP 当唯一身份凭证。

## 5. 游戏公平与信息隔离

生产洗牌使用 CSPRNG 和无偏 Fisher–Yates。随机种子/牌序不接受请求参数；调试固定牌堆仅存在测试装配，不注册生产容器。牌局命令串行，服务端计算按钮、行动顺序、合法动作、池和赢家。

内部 GameState 从不直接 JSON 化。所有网络、历史、管理、日志和机器人 context 使用显式字段白名单。测试通过改变他人底牌/未来牌但保持观察者可见面不变，断言投影完全相同。崩溃转储、APM 和异常上下文必须过滤私牌、牌堆和令牌。

## 6. 筹码与数据库安全

所有金额为整数并有非负/唯一/外键约束。资金事务使用业务幂等键、短写事务和提交后发布；不可只依赖内存。守恒失败停止受影响房间新开手，保留证据并人工审计，不以“补齐差额”掩盖错误。

SQLite 文件、WAL/SHM、备份和加密密钥仅服务账号可读；备份加密并定期恢复验证。生产服务账号最小权限，Nginx 用户不能读取密钥/数据库写目录之外的秘密。日志和数据库备份不得提交仓库。

## 7. 审计与隐私

管理员创建/禁用/重置、机器人配置、钱包调整、房间异常关闭、系统设置和 CLI 恢复均写追加审计：谁、何时、目标、原因、request_id 和安全的前后摘要。审计不含密码、session/ticket、完整 IP（可存受控摘要）或未公开牌。

仅收集运行所需的用户名、展示名和最小客户端元数据；不要求手机/邮箱。历史按参与者可见性返回。游客与练习数据按保留期清理。生产数据导出需管理员授权和审计。

## 8. 公开仓库与供应链

`.gitignore` 排除 `.env`、数据库/WAL/SHM、备份、日志、依赖目录和本地文件。仓库只提供 `.env.example` 占位值；任何真实 secret 由部署环境注入。提交前运行 secret scan 和依赖漏洞检查，锁定依赖版本，审核 Composer/npm 脚本。

机器人性格映射若希望不公开，应作为部署数据管理；公开源码常量不是秘密。当前不添加许可证，避免无意授予不明确权利。

## 9. 安全事件响应

发现会话/密钥泄露：撤销会话/票据、轮换密钥、检查审计；发现私牌泄露：停止相关房间和新开手、保存最小证据、修复投影并回归测试；发现账目异常：隔离写入、备份数据库、运行只读守恒/完整性检查，禁止手工直接改表。任何恢复通过版本化脚本、双人复核（条件允许）和审计执行。
