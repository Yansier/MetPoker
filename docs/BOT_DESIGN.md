# 机器人设计

## 1. 身份与生命周期

Bot Player 是无登录凭证的永久游戏身份，拥有唯一 player_id、名称、文字/SVG 头像、钱包、正式战绩、性格、难度和启用状态。部署初始化预置 12 名机器人，六类性格各两名；具体名称和映射存数据库，可由管理员修改，不假设公开仓库能保密源码常量。

机器人只有在真人所在房间由房主添加后才入座。最后一名真人离开后不再开始新手。禁用/移除/配置修改在当前手结束后生效；不得中途改变策略造成不公平。

普通房买入和再买入使用机器人自身钱包。设计默认：目标为房间默认买入；余额不足目标但达到最低买入时全额买入；低于最低买入则排队离桌。绝不自动生成永久筹码。练习房使用隔离临时栈，不触碰机器人钱包或正式战绩。

## 2. 最小策略接口

```php
interface BotStrategy
{
    public function decide(BotDecisionContext $context): BotDecision;
}
```

`BotDecisionContext` 是不可变且经过投影的数据：自身底牌、公共牌、座位/按钮相对位置、当前街道、公开的玩家栈/投入/弃牌/全押状态、底池、轮到机器人的合法动作及上下限、机器人的策略参数、该决策专用随机源。禁止包含牌堆、烧牌、未来公共牌、其他未公开底牌、账号资料、钱包总余额或管理员数据。

`BotDecision` 只能是合法动作类型与目标当前轮累计额；它只是意图。Realtime 延迟随机 1–3 秒后以普通 `Act` 命令提交，领域层再次验证当前 hand_id/version/轮次和合法范围。状态已变化则丢弃旧决策并重新计算，绝不强行执行。

## 3. 基础策略管线

1. 用起手牌组、位置和有效栈深形成翻牌前强度。
2. 翻牌后用自身牌与公共牌计算已成牌、听牌、公共牌湿润度；可采用有界 Monte Carlo 胜率估算，但采样只能从未知牌集合随机生成，不能读取真实剩余牌序。
3. 计算跟注成本、底池赔率、潜在赔率的保守近似和对手数量。
4. 性格参数调节入池率、主动性、诈唬频率、跟注阈值和下注尺度。
5. 难度调节估值精度、位置/赔率使用程度、采样数和明显错误率；错误也必须是合法动作。
6. 受控随机在若干近似等价动作间采样，避免完全可预测；随机源可在测试中复现。

首版不做长期对手画像、自学习、强化学习、外部 API 或自主策略进化。

## 4. 性格与难度

| 性格 | 入池范围 | 主动性 | 诈唬 | 典型倾向 |
|---|---|---|---|---|
| 紧弱 | 窄 | 低 | 很低 | 强牌入池，面对压力偏弃 |
| 紧凶 | 窄 | 高 | 中 | 强范围主动下注/加注 |
| 松弱 | 宽 | 低 | 低 | 跟注多，价值下注不足 |
| 松凶 | 宽 | 高 | 中高 | 频繁施压且波动大 |
| 诈唬 | 中 | 高 | 高但有上限 | 在合适牌面加入半诈唬/诈唬 |
| 均衡 | 中 | 中高 | 受控 | 多尺度混合，减少明显漏洞 |

难度与性格正交：简单使用粗粒度牌力并保留可配置的小概率次优选择；普通使用位置、赔率和牌面结构；困难增加采样精度、有效栈和下注尺度选择。困难不作弊，简单也不故意作出协议非法动作。

所有频率和阈值为配置数据，需限定范围并版本化。管理员修改生成审计记录，仅影响后续手牌。性格/难度默认仅管理员可见，是否公开为 `DECISIONS.md` 的 Q-001。

## 5. 信息隔离与安全测试

- 通过显式白名单构造 context，禁止把 `GameState` 直接传入策略。
- 生产日志只记录决策输入的公开摘要、策略版本和输出，不记录底牌以外私有牌；普通玩家不得下载策略参数。
- 测试使用两份内部状态：只改变对手底牌/未来牌，保持投影相同，断言 context 完全相同。若使用确定性随机，输出也必须相同。
- 模拟测试断言所有输出都在合法集合，超时/异常采用安全降级：可 check 则 check，否则 fold。
- 机器人进程不得直接访问 PDO、会话或 WebSocket；钱包操作由应用服务完成。

## 6. 模拟与验收指标

每种性格/难度运行固定种子和随机种子模拟，覆盖 2–9 人、不同栈深、全押/边池、短码加注权及余额耗尽。验收关注非法动作数（必须为 0）、信息泄露（必须为 0）、筹码漂移（必须为 0）、决策时延上界和不同性格的统计可区分性；不以短期盈利率承诺机器人“最优”。
