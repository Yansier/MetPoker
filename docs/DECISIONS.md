## 已确认

| 编号 | 决策 |
|---|---|
| D-001 | 标准无限注现金桌，2–9 人，无抽水、不自动升盲；首版无锦标赛、前注、Straddle、保险和多次发牌。 |
| D-002 | PHP 8.2+ 纯领域引擎，Vue 3 前端，Workerman WebSocket，SQLite/PDO，单服务器单权威游戏进程。 |
| D-003 | Account 与 Player 分离；Bot Player 永不登录，管理员参局时无额外牌局权限。 |
| D-004 | 普通房永久筹码与练习房临时筹码严格隔离，整数金额、非负约束、正式筹码守恒。 |
| D-005 | 机器人只能看到自身底牌和公开信息，经过与真人相同的合法动作校验；不得无人持续游戏。 |

| D-007 | Phase 1A 只交付文档和骨架，不安装依赖、不建库、不实现业务、不部署、不推送。 |

### Phase 1A.1 所有者确认（保留 Q 编号）

| 追溯编号 | 已确认决策 |
|---|---|
| Q-001 | 机器人**难度公开、性格隐藏**。普通玩家可见名称、头像、机器人标识、难度及允许公开的资产/战绩；性格、策略参数、诈唬频率、阈值和私有决策上下文仅管理员可见。配置修改在手牌结束后生效。 |
| Q-002 | 机器人仅在桌上筹码归零时于两手之间自动再买入：优先默认买入；钱包不足默认但达到最低时使用不超过上限的全部余额；低于最低则离桌。正栈不自动补满，练习房只补临时筹码。 |
| Q-003 | 首版不提供自愿展示已弃底牌，不存在 `SHOW_CARDS` 动作；规则要求的正常摊牌不受影响。 |
| Q-004 | 邀请码默认 7 天、一次成功使用、可提前撤销；仅存安全摘要。邀请码消耗、Account/Player/初始钱包创建在同一事务，并发只能成功一次。 |
| Q-005 | 登录用户名创建后不可修改；展示昵称可按安全规则修改并审计；历史和资金始终关联永久 Player ID。 |
| Q-006 | 暂不添加 LICENSE，不自动声明任何开源授权。 |

## 设计默认值

| 编号 | 默认方案 | 理由/生效边界 |
|---|---|---|
| D-101 | 掉线座位保留 120 秒；空房 30 分钟回收，仅旁观者房 15 分钟回收。 | 可配置；多人桌计时不停，单真人桌自动暂停。 |
| D-102 | 房主离开后转给已连接且最早入座的注册真人；无人可接则关闭。 | 避免转给游客/机器人；当前手先按规则收尾。 |
| D-103 | 奇数筹码从按钮左侧第一个仍有资格的获胜者起按顺时针、每次一枚分配。 | 固定、可测试，不按花色决定。 |
| D-104 | 单挑按钮是小盲，翻牌前先行动；翻牌后大盲先行动。 | 标准单挑现金桌口径。 |
| D-105 | 不足额全押单次或累计达到最近一次完整下注/加注幅度时，才对已行动玩家重新开放加注权。 | 以玩家面对的累计增量判定，详见规则文档。 |
| D-106 | 普通河牌摊牌由最后主动下注/加注者先亮；无人下注则按钮左侧首位先亮；获奖牌必须公开，未公开弃牌不进入公共历史。 | 本人私有历史按 D-113 分栏。 |
| D-107 | 崩溃后未提交结算的手牌全部作废，恢复开手检查点；已提交结算不回滚。旧房间关闭并返还桌上余额。 | 恢复可幂等，不强求实时画面续局。 |
| D-108 | SQLite 启用 WAL、foreign_keys、busy_timeout=5000ms；写事务采用短事务和有界退避，最多约 10 秒后失败。 | 具体退避参数实现时压测确认。 |
| D-109 | state_version 每个成功事件批次递增；请求去重记录至少保留房间生命周期加 24 小时，结算幂等键永久保留。 | 支持断线重试和审计。 |
| D-110 | 预置 12 个机器人在部署初始化时生成，其性格映射存数据库配置而非需要保密的源码常量。 | 公开仓库不提供虚假秘密。 |
| D-111 | 加注权按玩家分别计算；即使权利重开，没有任何可行动对手时也不能制造额外下注。`all_in` 不绕过该限制。 | Phase 1A.1 规则设计默认值。 |
| D-112 | 固定逐张两轮发底牌及每条公共街烧一张的牌序；全押跑牌同样执行，提前结束不再发牌。 | 支持确定性测试。 |
| D-113 | 有效正式手可加密保留注册真人自己的私有历史底牌；公开牌分栏保存。机器人未公开牌和作废手私牌不保留。 | 管理员无越权读取能力；不声称抵御主机 root。 |
| D-114 | 练习房允许 Guest Principal 成为房主；普通房房主必须是 Account Principal，机器人永不成为房主。 | 房主授权绑定服务端认证主体。 |
| D-115 | 新连接/重新认证总是先接收裁剪快照；同一已认证连接发生短暂版本缺口时，才允许按接收者重新投影后补发事件批次。不可安全判断则再次快照。 | 消除重连顺序与私有事件泄露歧义。 |
| D-116 | 行动任务用 `hand_id + turn_id + acting_player_id + timer_generation` 判定；`state_version` 只负责同步与普通冲突。 | 无关房间事件不影响行动计时。 |
| D-117 | 所有筹码整数的统一上限为 `1_000_000_000_000`；PHP 必须为 64 位，SQLite INTEGER 与 JS 安全整数均可精确承载。 | 所有中间结果也必须在上限内，否则拒绝事务。 |
| D-118 | 管理员密码重置凭证默认 15 分钟有效、仅可使用一次且数据库只存摘要；完成改密前处于受限认证态。 | 有效期可配置，Phase 2A 安全测试确认。 |
| D-119 | 只有全部投注行动结束且不可能再下注时，才在跑剩余公共牌前公开所有仍有资格的全押底牌；普通河牌仍按 D-106 顺序并允许明确输家 muck。 | 固定全押公开边界，避免提前泄露。 |

## 规则冲突处理

发现文档冲突时：安全/隐私和筹码守恒不降级；牌局规则以 `POKER_RULES.md` 为准，数据事务以 `DATABASE.md` 为准，线协议分别以 API/WS 契约为准。冲突必须先更新本文形成单一决策，再进入实现，禁止用代码默默选择另一方案。
