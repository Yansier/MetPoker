# 产品需求文档（PRD）

## 1. 产品目标与非目标

MetPoker 为个人及少量受邀朋友提供可信、可恢复的网页端无限注德州扑克体验。成功标准是：规则结果可验证、未公开信息不泄露、永久筹码账目可追溯、断线或崩溃不会造成重复结算，并能在普通桌与练习桌间清楚切换。

首版不涉及真实货币或任何兑换，不提供公开大厅商业运营、锦标赛、前注、Straddle、保险、多次发牌、玩家转账、充值提现、AI 大模型、长期对手画像或复杂数据图表。

## 2. 用户与身份

| 类型 | 登录 | 游戏身份 | 永久钱包 | 正式战绩 | 管理能力 |
|---|---:|---:|---:|---:|---:|
| 管理员 | 是 | Human Player | 是 | 是 | 是，且无牌局内特权 |
| 注册玩家 | 是 | Human Player | 是 | 是 | 否 |
| 永久机器人 | 否 | Bot Player | 是 | 是 | 否 |
| 游客 | 临时会话 | Guest Player | 否 | 否 | 否 |

Account 只表达登录、角色与会话；Player 只表达可入座的身份。一个真人账号关联一个永久真人 Player。机器人永远不创建 Account，游客 Player 在会话/保留期后回收。

## 3. 核心用户流程

### 3.1 账号与访问

- 管理员可创建账号、生成默认 7 天有效且仅可成功使用一次的邀请码、重置密码、禁用/解禁账号。邀请码只存安全摘要，可提前撤销；成功消费与 Account、Human Player、初始钱包创建必须同事务提交。
- 公开注册默认关闭，游客模式默认开启；不收集手机、邮箱或第三方账号。
- 用户可修改自己的密码。管理员重置生成一次性、短时有效的重置凭证并撤销旧会话、未使用 WS ticket 和已认证连接权限；用户进入受限认证态，完成改密前只能查询必要自身认证状态、改密和退出。
- 登录用户名创建后不可修改；展示昵称可以按长度/安全字符规则修改并审计。历史、钱包和战绩永远使用稳定 Player ID 关联。
- 服务器 CLI 可创建首个管理员并恢复管理员密码；操作必须在服务器本机执行并写审计记录，不能包含固定密码或 Web 后门。

### 3.2 私人房间

创建者成为房主，通过房间码或链接邀请成员。普通房房主必须是注册真人；游客可创建并管理练习房，房主授权绑定服务端认证 principal，机器人不能成为房主。房主可添加/移除机器人、管理座位、踢人、暂停下一手或解散房间；影响当前手公平性的操作排队到手牌结束。正常解散不能作废亏损手牌：先安全完成当前手，再原子返还正式桌上余额；仅系统异常才允许受审计作废。

默认值：6 座、50/100 盲注、20–100 BB 买入、默认 100 BB、真人 30 秒行动、机器人随机 1–3 秒、允许旁观、自动下一手、可选密码。座位范围 2–9；具体配置边界由后端验证。

配置分三类：房间密码/旁观开关立即影响新请求；自动下一手和房主“暂停下一手”在手牌边界生效；盲注、买入范围和座位上限仅在无进行中手牌且不会使现有座位非法时生效。仅一名真人时，该在座真人的主动暂停是独立的即时命令，可在行动倒计时内冻结当前手，不等待手牌边界。

### 3.3 普通房

仅注册真人和启用的永久机器人可入座。买入从各自永久钱包扣至桌上托管余额；追加买入在两手之间生效；离桌余额返还钱包。正式净盈亏只统计牌局结算，不包含管理员调整。

例：玩家钱包 100,000，以 10,000 买入，钱包变 90,000、桌上 10,000；牌局净赢 2,500 后以 12,500 离桌，钱包变 102,500，正式累计净盈亏增加 2,500。买入和返还本身不算盈利。

### 3.4 练习房

注册玩家和游客均可参加；临时筹码只属于房间参与记录，可免费补充，不接触 `wallets`/正式流水/正式战绩。练习房复用完全相同的规则引擎、合法动作校验和机器人策略接口，但永久机器人参加练习房时也使用临时栈。

### 3.5 暂停、旁观、离线和离桌

- 仅一名真人入座时，该在座真人可主动暂停；主动暂停不受普通行动倒计时限制，并冻结行动剩余时长和机器人任务。该真人断线则进入不同的自动暂停流程，重连后由服务端恢复。
- 两名及以上真人入座时不得单方面暂停。行动超时时：可过牌则自动过牌，否则自动弃牌。
- 旁观者不占座、不发动作、永远看不到未公开底牌。申请入座/替换机器人在当前手结束后执行。
- 掉线座位默认保留 120 秒。单真人意外断线在期限内自动暂停；超期后标记待离桌、退出自动暂停并以合法自动 check/fold 收尾。多人桌断线不暂停且继续计时。已全押者始终保留结算资格。
- 房主离开时依次转移给当前已连接、最早入座的注册真人；没有注册真人则房间进入待关闭。最后一名真人离开后禁止开始新手牌。
- 游客房主离开或凭证过期也按上述规则转移；无注册真人候选时安全收尾并关闭，练习资源按保留期回收。
- 无成员房间默认空闲 30 分钟回收；只有旁观者且无牌局的房间默认 15 分钟回收。上述期限均为可配置设计默认值。

## 4. 游戏规则范围

标准 52 张牌、2–9 人、无限注现金桌，无抽水且盲注不自动增长。支持翻牌前至河牌和摊牌，动作包括弃牌、过牌、跟注、下注、加注、全押；必须正确处理单挑、按钮/盲注轮换、不足盲注、最小加注、短码全押、未跟注退还、多层边池、平局和奇数筹码。固定口径见 `POKER_RULES.md`，其优先级高于 UI 文案。

## 5. 机器人需求

系统预置 12 个永久机器人：紧弱、紧凶、松弱、松凶、诈唬、均衡各两个；难度（简单/普通/困难）独立配置。普通玩家可见机器人标识、名称、头像、难度和允许公开的资产/战绩；性格及策略参数仅管理员可见。配置修改在手牌结束后生效。

机器人与真人经过同一动作命令与合法性校验。其决策上下文仅含自身底牌、公共牌、公开下注、位置、底池、合法动作和必要配置；不得包含其他底牌、牌堆或未来牌。普通房只有桌上筹码归零时才在两手之间自动再买入：钱包足够则买默认额，不足默认但达到最低则使用不超过上限的全部余额，低于最低则离桌；正栈不自动补满。练习房只免费补临时筹码。

同一永久 Player（真人或机器人）同一时间最多占一个有效牌桌座位，防止同一钱包/机器人跨房间并发使用；可同时旁观其他房间。机器人被动参与，禁止自主组桌或无人持续游戏。

## 6. 永久筹码与审计

每个永久 Player 默认初始 100,000 整数筹码（可配置）。玩家不能领取、签到、自动补充或互转；只有管理员能调整钱包，管理员调整自己也一样审计。禁止直接修改正在参局的桌上筹码。

正式资金事件包括初始发放、管理员调整、买入/追加、结算、离桌返还和异常恢复。每项使用唯一业务键、数据库事务和双向可核对流水。任何时刻应满足：系统永久筹码总量 = 全部钱包余额 + 全部正式桌托管余额；只有初始发放和管理员调整改变总量。

## 7. 战绩口径

- `hands_played`：玩家获发底牌且该正式手最终有效结算；作废手不计。
- `hands_won`：至少从一个底池获得份额；平分也算赢牌手数一次，但另记 `split_pot_hands`。
- 赢牌率：`hands_won / hands_played`；零手显示 0，不制造除零值。
- 正式累计净盈亏：`gross_committed` 是原始投入，`uncalled_returned` 是未跟注退还，`net_committed = gross_committed - uncalled_returned`，`pot_awarded` 只含主/边池奖励；`net_game_profit = pot_awarded - net_committed = final_stack - opening_stack`。退还不重复算奖励，每手全体之和必须为零。
- 最大单手净赢/净输：基于上述逐手净值；弃牌投入计亏损，边池分别求和后归入该手。
- 主要牌型：仅对实际摊牌且可评估的最终最佳五张牌统计；未摊牌弃牌不推断牌型。
- 当前永久总资产：钱包 + 正式桌托管余额；历史最高资产在有效资金事务提交后更新。
- 管理员累计发放/扣除单独统计，绝不并入游戏盈亏。
- 进行中手不进入正式统计；练习房任何数据不进入正式战绩。

有效正式手可为注册真人加密保留其自己的历史底牌，并与公开牌分栏存取；只有本人可读。管理员未参与该手时不能读取他人私牌，参与时也只有普通玩家的本人权限。机器人未公开牌、作废手私牌和完整剩余牌堆不保留；日志不记录私牌。

## 8. 管理后台

同一 Vue 工程规划 `/admin` 路由，后端逐接口验证管理员角色。功能包括系统概览、账号/资料/会话管理、机器人配置、钱包调整和流水、战绩、活跃房间、异常关闭、基础设置及管理员审计。后台永不提供未公开底牌、牌堆、发牌控制、桌上筹码编辑或机器人即时操控。

## 9. 可用性与质量

- 中文为默认语言；深色背景、墨绿色牌桌，图形使用 CSS/SVG/文字，不依赖外部图片。
- 新连接和重新认证必须先获得全量身份裁剪快照。同一已认证连接出现短暂版本缺口时，只有能按当前主体安全重投影的连续批次才补发；仅含他人私有事件的批次用空投影确认推进版本，不安全则重新快照。
- 关键资金操作和结算可安全重试；异常重启不会重复发放、重复结算或丢失托管筹码。
- 规则引擎必须支持确定性随机、注入时钟及完整边界测试。

## 10. 首版验收边界

Phase 1A 只交付可执行的设计契约与目录骨架，不实现引擎、机器人、登录、数据库、页面或服务。各后续阶段的范围与退出条件见 `ROADMAP.md`；端到端验收与关键测试见 `ACCEPTANCE.md`。
